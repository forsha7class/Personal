05 / ABOUT

Systems first, decoration second.

I am Dika. I build software systems and the structure around them — the interface people touch, the state that sits behind it, and the checks that keep both honest.

My background sits at the intersection of law and technology. That shows up less as legal content and more as a working habit: define the rules, make failure modes explicit, and be able to explain why the system behaves the way it does.

I prefer small systems that can be read end to end. The builds on this site are public for that reason — you can open the source, run them, and disagree with my choices.

  • Evidence over adjectives If it cannot be opened, run or read, it does not go on the page.
  • Boring where it counts Predictable state, explicit failure modes, no magic in the critical path.
  • Accessible by default Keyboard paths, focus states and contrast are part of the build, not a cleanup pass.
